# 文档文风规范 v2

> 适用范围：本仓库所有面向读者的 Markdown（分册 README / computer-use / browser-use / comparison / reusable / 根 README）。
> evidence/inventory.md 是数据文件，不强制本规范。
> 起因：v1 文档文字密度过高、不直观。本规范的目标是**每屏有一张表或一张图**。

## 核心原则

**图 > 表 > 列表 > 段落。** 段落最多 3 行；连续段落不超过 2 个，之后必须出表格或图。

## 结构模板（每份分册文档）

### 1. 开头「30 秒速览卡」（必须有）

```markdown
# <名称>（<厂商>）· <一句话定位>

> 一句话结论：**<这家最独特的一点>**

| 项 | 值 |
|---|---|
| 载体 | <二进制/app/插件 + 版本> |
| 形态 | <独立 Helper / MCP / 内嵌 / 云端 / 透传> |
| CU 工具面 | <N 个工具 · 核心机制 5 字> |
| BU 工具面 | <N 个工具 · 架构 5 字> |
| 安全模型 | <3-5 字要点> |
| 本机可用 | ✅ / ⚙️未启用 / ❌链路断（2026-10 基线） |
```

### 2. 架构一图（必须有，紧接速览卡）

ASCII 分层图 ≤14 行，箭头标注协议/通道：

```
模型
 └─ js MCP 工具（唯一入口）
     └─ SDK  agent.computerUse（Symbol 桥接）
         └─ 宿主会话  state_id/frame_id 台账
             └─ Helper  broker.sock（JSON-RPC）
                 └─ ax_native.node  AX / CGEvent / ScreenCaptureKit
```

### 3. 正文小节（每节 ≤3 个小节）

- 标题 = **结论式短语**：「动作：AX 语义优先，CGEvent 兜底」而非「动作机制分析」
- 每节第一行 = **粗体一句话结论**（answer-first）
- 工具清单 → 表格（工具 / 参数要点 / 一句话语义）；schema 细节一律指向 `source/<slug>/schemas/`，正文不重复
- 与别家对比 → 小矩阵表，不写文字对比段

## 语言纪律

- 段落 ≤3 行；句子 ≤40 字；不用"首先/其次/此外/综上"
- 数字进表格，结论进粗体，演进史一行脚注：`> 演进：v1 屏幕级 30 工具 → v2 收敛 14 个（2026-09）`
- 事故故事压缩成一行：`> 来源：某会话 3 次静默点击失败（2026-09-17）`
- 术语首次出现给白话括号：AX 树（系统无障碍接口暴露的控件树）
- 删除客套话、元话语（"值得注意的是"）、重复的合规声明（全文一处）

## 行数预算

| 文档 | 预算 |
|---|---|
| 分册 README | ≤90 行 |
| computer-use.md | ≤180 行 |
| browser-use.md | ≤150 行 |
| 根 README | ≤180 行 |
| evidence/inventory.md | 不限（数据文件） |

## 禁止

- 大段引用源码（>5 行进 evidence）
- 一层套一层的嵌套列表（最多两层）
- 无表格支撑的纯文字小节超过连续 2 个
- markdown 里的 HTML（GitHub 渲染不一致）
