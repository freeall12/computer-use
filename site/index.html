这是什么：一项对 12 个 Coding Agent 桌面控制能力的只读逆向研究

Agent Computer Use Atlas 是对 12 个主流 Coding Agent 在同一台 macOS 机器上的桌面控制（Computer Use / CU）与浏览器控制（Browser Use / BU）能力所做的只读静态逆向研究：48 份分册文档（7400+ 行中文证据链）、12 维能力矩阵、20 个可复用设计模式与 12 套可运行参考实现，回答三个问题——它们怎么实现的？谁抄谁？我们能学到什么？分析基线为 2026-10-06（macOS arm64，各产品当日本机安装版本）。在线主站：https://freeall12.github.io/computer-use/，源仓库：github.com/freeall12/computer-use。

12 个 Agent 速览（名字 · 厂商 · CU/BU 能力一句话）

ZCode（智谱）

Computer Use：14 工具 · ax_native Helper（AX+CGEvent）。Browser Use：内嵌 WebView · 单一 js 工具动态面。结论：安全加固最重的自研派——CU SDK 逐字对齐 Codex @oai/cua，stateId / possibly_sent / controller lease / kill switch 为事故驱动的自研加固。

核心发现 TL;DR（8 条）

  1. 四种执行基线：本地 Helper/驱动执行（9 家）、全云端执行本地投影（Devin）、执行层外包透传（Goose）、完全无原生能力（Grok CLI）。
  2. 白牌供应链出现了：Grok Bot 桌面端由 Anysphere（Cursor 母公司）整体代工换牌，签名 TeamID 与 Cursor 完全一致，安全模型随代工继承。
  3. 四条公开底座被复用：Cua AI（MiniMax/Synara 内嵌 cua-driver、Kimi 致谢其键盘机制）、qwen-code（Qoder 内核确证迁自）、Peekaboo（Goose 全部桌面执行层）、Codex sky（MiMo 明示清洁室复刻）。
  4. ZCode 的 CU SDK 逐字对齐 Codex @oai/cua（0.2.4），但 stateId / frameId / possibly_sent / controller lease / kill switch 是事故驱动的自研加固。
  5. 观察以 AX diff 为主：Goose 是 12 家中唯一在 CU 主路径使用「截图叠元素编号」的（基于 AX 树的 SoM 变体）；防句柄漂移有五级方案光谱。
  6. 后台定向输入（不抢焦点）四路线：AX 写值、窗口相对事件路由、SLS 签名事件封包（Kimi）、SkyLight/CGS 私有 API（Claude / MiMo / Grok）。
  7. Browser Use 三架构：内嵌 WebView、真浏览器扩展、云端浏览器各有实例；成熟产品走向「多后端 + 能力广告」统一对象面。
  8. MCP 是万能挂载面（八种形态）：共同点是「未启用 = 工具不存在」的 fail-closed 门控；防重放与「投递≠生效」验证回读是安全模型的最高共识。

常见问题（FAQ）

这项研究覆盖了哪 12 个 Agent？

ZCode（智谱）、Codex（OpenAI）、Claude Code（Anthropic）、Cursor（Anysphere）、MiniMax Code、Synara（独立开发者）、Kimi Code（月之暗面）、Qoder（阿里巴巴）、Grok Bot（xAI）、Devin（Cognition）、Goose（Block）、MiMo（小米）。分析基线为 2026-10-06 的 macOS arm64 本机安装版本，方法为只读静态逆向，未运行被分析对象、未抓包。

哪些 Agent 用了开源 Cua AI（trycua）底座？

MiniMax Code 内嵌 trycua cua-driver 0.22.1（17 个 CU 工具）；Synara 使用 cua-driver 0.28.2 patched（33 个 CU 工具）；Kimi Code 公开致谢了 Cua AI 的 SLS 签名键盘机制。其余多数为自研 Helper 或驱动。

为什么说 Grok Bot 和 Cursor 同源？

Grok Bot 桌面端由 Anysphere（Cursor 母公司）整体代工换牌：签名 TeamID「DCNK4UB866」与 Cursor 完全一致、sidecar 走 downloads.cursor.com CDN、asar 包名 sand、JS 残留 CUCursorService、模型名同为 sand-cua。

12 家 Agent 的 Computer Use 有哪几种执行基线？

四种：本地 Helper/驱动执行（9 家）、全云端执行本地投影（Devin）、执行层外包透传（Goose）、完全无原生能力（Grok CLI）。

谁复制了谁？有哪些谱系关系实锤？

ZCode CU SDK 自述逐字对齐 Codex @oai/cua 0.2.4；Qoder node_repl 内核确证迁自 qwen-code（Apache-2.0）；MiMo 自述受 Codex sky 启发，是明示的清洁室复刻；Goose 执行层来自 Peekaboo（MIT）；Grok Bot 由 Cursor 母公司代工。

研究内容可以复用吗？包含什么？

可以，MIT 许可开源。含 48 份分册文档（7400+ 行中文证据链）、12 维能力矩阵、20 个可复用设计模式与 12 套可运行参考实现；不含任何专有源码、二进制或凭据，不含 DRM 规避。
